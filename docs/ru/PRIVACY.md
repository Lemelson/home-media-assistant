# Данные и приватная эксплуатация

[English](../en/PRIVACY.md)

Это перечень для оператора, а не обещание анонимности и не готовая политика публичного сервиса. Репозиторий не предоставляет облачный backend и не содержит центрального адреса телеметрии автора.

| Компонент | Какие данные получает или хранит |
|---|---|
| Telegram | ID, сообщения, вложения, голос, ответы, показанные имена файлов и статусы; чаты с ботом не являются секретными чатами со сквозным шифрованием |
| Состояние бота | SQLite: попытки доступа, участники, контекст, очередь, поиск, доставка, прогресс и идентификаторы |
| Состояние агента | Владение загрузками, идентификаторы и метаданные торрентов, пути и имена файлов, история прогресса; секреты в локальном JSON |
| Transmission и участники обмена | Идентификаторы, файлы/части и сетевые адреса; участникам виден IP соединения |
| Plex, необязательно | Метаданные библиотеки и действия аккаунта согласно настройкам сервиса; локальная интеграция читает существующий Plex-токен пользователя |
| OpenRouter и провайдер модели | Запросы и ограниченный контекст; имена и пути файлов для фонового переименования; звук при выбранном распознавании |
| Exa и Prowlarr | Поисковые запросы; Prowlarr передаёт их настроенным индексаторам, Exa является внешним сервисом |
| Groq | Голос для распознавания |
| TMDB, Serper и хосты изображений | Запросы картинок; Telegram может загружать указанные внешние URL |

Пустые API-ключи отключают интеграции. Голос и картинки дополнительно включаются отдельными флагами. Отключённое распознавание не мешает Telegram получить голосовое, отправленное пользователем. SQLite не шифруется приложением: права файлов, защита аккаунта ОС, шифрование диска и резервные копии остаются задачей оператора. Сроки хранения и международные передачи провайдеров программа не контролирует.

Используйте отдельного приватного бота, числовые ID, локальный RPC и ограниченный SSH-туннель. Не помещайте `.env`, `agent-state`, `runtime`, ключи, backups и диагностику в Git. Не публикуйте `/access`, содержимое баз и скриншоты с идентификаторами. Отключите ненужные API и изучите правила каждого включённого сервиса.

Часть историй ограничена, но **единого срока хранения и полного удаления данных отдельного человека нет**. Записи доступа и очереди могут сохраняться. Не называйте это автоматическим соответствием GDPR. Для использования за пределами семьи нужно отдельно спроектировать и проверить сроки хранения, удаление, информирование и доступ.

## Сброс установки

Остановите бот и агент; при необходимости остановите Transmission, отзовите ненужные ключи и приватно сохраните нужные записи. Для удаления данных приложения удалите только проверенные папки состояния бота и агента. Это сбросит доступ, очередь и привязку владельцев загрузок. Сами медиафайлы, Telegram, Transmission, Plex и копии у провайдеров не удаляются; ими нужно управлять отдельно. После сброса существующие загрузки могут потребовать ручного управления.

## Публикация исходников

Репозиторий на существующем GitHub-профиле видимо связан с этим профилем. Новая история Git и `noreply` скрывают старые коммиты и личную почту из новых коммитов, но не публичный профиль, активность, форки и кеши. Проверка состава релиза — ограниченное доказательство, а не гарантия отсутствия секретов во всех будущих изменениях. Утёкший секрет нужно отозвать у провайдера: удаления файла недостаточно.

Модуль восстановления также делает ограниченные TCP-проверки двух фиксированных адресов публичной инфраструктуры. Данные приложения не передаются, но получателям виден исходящий IP. Сканер разрешает только эти проверенные константы в конкретном модуле; адреса серверов оператора не разрешены.
